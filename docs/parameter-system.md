# Parameter System

This document describes the complete parameter model used by Advanced EQ, including the APVTS layout, parameter ID conventions, lock-free audio thread access, and UI attachment patterns.

## Overview

The plugin manages **298 total parameters** through JUCE's `AudioProcessorValueTreeState` (APVTS):

- **288 band parameters**: 24 bands x 12 parameters per band
- **10 global parameters**: output gain, pan, processing mode, oversampling, auto-gain, analyzer controls, analog mode

All parameters are created in `source/parameters/ParameterLayout.cpp` and registered with the APVTS at construction time.

**Source files**:
- `source/parameters/ParameterIDs.h` -- ID constants and name arrays
- `source/parameters/ParameterLayout.h` / `.cpp` -- APVTS layout factory
- `source/parameters/BandParameterAttachment.h` -- Lock-free audio thread bridge

## Parameter ID Convention

### Band Parameters

Format: `band_XX_suffix` where XX is a zero-padded two-digit band index (00-23).

Generated by the helper function:

```cpp
// source/parameters/ParameterIDs.h
juce::String bandParam (int bandIndex, const juce::String& param)
{
    return "band_" + juce::String (bandIndex).paddedLeft ('0', 2) + "_" + param;
}
```

Examples:
- `band_00_freq` -- Band 0 frequency
- `band_05_gain` -- Band 5 gain
- `band_23_type` -- Band 23 filter type

### Global Parameters

Global parameters use simple string IDs without the `band_XX_` prefix:

```
output_gain, output_pan, process_mode, oversample, auto_gain,
analyzer_on, analyzer_pre, analyzer_res, analyzer_speed, analog_mode
```

## Per-Band Parameters (x24)

Each of the 24 bands has 12 parameters:

| Suffix | JUCE Type | Range | Default | Unit | Skew | Description |
|--------|-----------|-------|---------|------|------|-------------|
| `active` | `AudioParameterBool` | 0/1 | false | -- | -- | Band enabled/bypassed |
| `type` | `AudioParameterChoice` | 0-8 | 0 (Bell) | FilterType enum | -- | Filter shape |
| `freq` | `AudioParameterFloat` | 10-30000 | 1000 | Hz | 0.3 (log) | Center/cutoff frequency |
| `gain` | `AudioParameterFloat` | -30 to +30 | 0 | dB | linear (step 0.01) | Boost/cut amount |
| `q` | `AudioParameterFloat` | 0.1-30 | 1.0 | -- | 0.4 (log) | Quality factor |
| `slope` | `AudioParameterChoice` | 0-8 | 1 (12dB) | slope index | -- | Filter slope |
| `stereo` | `AudioParameterChoice` | 0-4 | 0 (Stereo) | StereoPlacement enum | -- | Stereo routing |
| `dyn_on` | `AudioParameterBool` | 0/1 | false | -- | -- | Dynamic EQ enabled |
| `dyn_thresh` | `AudioParameterFloat` | -60 to 0 | -20 | dB | linear (step 0.1) | Dynamic threshold |
| `dyn_range` | `AudioParameterFloat` | -30 to +30 | 0 | dB | linear (step 0.1) | Dynamic range |
| `dyn_attack` | `AudioParameterFloat` | 0.1-500 | 10 | ms | 0.35 (log) | Dynamic attack time |
| `dyn_release` | `AudioParameterFloat` | 1-5000 | 100 | ms | 0.35 (log) | Dynamic release time |

### Slope Index Mapping

| Index | Display Name | dB/oct Value | Notes |
|-------|-------------|-------------|-------|
| 0 | 6 dB/oct | 6 | 1st order, 1 section |
| 1 | 12 dB/oct | 12 | 2nd order, 1 section (default) |
| 2 | 18 dB/oct | 18 | 3rd order, 2 sections |
| 3 | 24 dB/oct | 24 | 4th order, 2 sections |
| 4 | 36 dB/oct | 36 | 6th order, 3 sections |
| 5 | 48 dB/oct | 48 | 8th order, 4 sections |
| 6 | 72 dB/oct | 72 | 12th order, 6 sections |
| 7 | 96 dB/oct | 96 | 16th order, 8 sections |
| 8 | Brickwall | 0 (special) | 8 sections, maximum attenuation |

Conversion is handled by `slopeIndexToDBPerOct()` in `FilterTypes.h`.

### Stereo Placement Index

| Index | Name | Enum Value | Processing Pass |
|-------|------|------------|-----------------|
| 0 | Stereo | `StereoPlacement::Stereo` | Pass 1 (both channels) |
| 1 | Left | `StereoPlacement::Left` | Pass 2 (left only) |
| 2 | Right | `StereoPlacement::Right` | Pass 3 (right only) |
| 3 | Mid | `StereoPlacement::Mid` | Pass 4 (M/S encoded) |
| 4 | Side | `StereoPlacement::Side` | Pass 4 (M/S encoded) |

### Logarithmic (Skewed) Parameters

Several parameters use JUCE's `NormalisableRange` skew factor for logarithmic scaling in the UI:

- **Frequency** (skew 0.3): Maps the 10-30000 Hz range so that the middle of the slider corresponds to approximately 300 Hz rather than 15000 Hz. The 0.3 skew factor produces a pseudo-logarithmic distribution.
- **Q** (skew 0.4): Maps 0.1-30 with emphasis on the lower range where most practical Q values (0.3-5.0) reside.
- **Dynamic Attack** (skew 0.35): Maps 0.1-500 ms with emphasis on fast attacks.
- **Dynamic Release** (skew 0.35): Maps 1-5000 ms with emphasis on shorter release times.

## Lock-Free Audio Thread Access

### BandParameterAttachment

**File**: `source/parameters/BandParameterAttachment.h`

The `BandParameterAttachment` class is the bridge between the APVTS (owned by the message thread) and the DSP engine (running on the audio thread). It eliminates all per-block overhead:

#### Initialization (Message Thread, Once)

```cpp
void init (int bandIndex, juce::AudioProcessorValueTreeState& apvts)
{
    rawActive     = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kActive));
    rawType       = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kType));
    rawFreq       = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kFrequency));
    rawGain       = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kGain));
    rawQ          = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kQ));
    rawSlope      = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kSlope));
    rawStereo     = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kStereo));
    rawDynEnabled = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kDynEnabled));
    rawDynThresh  = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kDynThresh));
    rawDynRange   = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kDynRange));
    rawDynAttack  = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kDynAttack));
    rawDynRelease = apvts.getRawParameterValue (ParamIDs::bandParam (bandIndex, ParamIDs::kDynRelease));
}
```

`getRawParameterValue()` returns a `std::atomic<float>*` that points directly into the APVTS's internal storage. These pointers are stable for the lifetime of the APVTS.

#### Audio Thread Read (Every processBlock)

```cpp
BandParameters getCurrentParameters() const
{
    BandParameters params;
    params.active           = rawActive->load() > 0.5f;
    params.type             = static_cast<FilterType> ((int) rawType->load());
    params.frequency        = rawFreq->load();
    params.gain             = rawGain->load();
    params.q                = rawQ->load();
    params.slopeDBPerOct    = slopeIndexToDBPerOct ((int) rawSlope->load());
    params.stereoPlacement  = static_cast<StereoPlacement> ((int) rawStereo->load());
    params.dynamicEnabled   = rawDynEnabled->load() > 0.5f;
    params.dynamicThreshold = rawDynThresh->load();
    params.dynamicRange     = rawDynRange->load();
    params.dynamicAttack    = rawDynAttack->load();
    params.dynamicRelease   = rawDynRelease->load();
    return params;
}
```

This produces a `BandParameters` struct with:
- **Zero heap allocations**: The struct is stack-allocated and returned by value
- **Lock-free reads**: Each `load()` is an atomic read (default `memory_order_seq_cst` from JUCE's `std::atomic<float>`)
- **Type conversions**: Choice parameters are cast from float to int, then to enum. Bool parameters are threshold-compared against 0.5. The slope index is converted to dB/oct via `slopeIndexToDBPerOct()`.

### Global Parameter Access

The processor caches four global parameter pointers directly:

```cpp
// source/PluginProcessor.h
std::atomic<float>* rawOutputGain = nullptr;
std::atomic<float>* rawAnalyzerOn = nullptr;
std::atomic<float>* rawAnalyzerPre = nullptr;
std::atomic<float>* rawAnalogMode = nullptr;
```

These are initialized in the constructor:

```cpp
rawOutputGain  = apvts.getRawParameterValue (ParamIDs::kOutputGain);
rawAnalyzerOn  = apvts.getRawParameterValue (ParamIDs::kAnalyzerOn);
rawAnalyzerPre = apvts.getRawParameterValue (ParamIDs::kAnalyzerPre);
rawAnalogMode  = apvts.getRawParameterValue (ParamIDs::kAnalogMode);
```

And read in `processBlock()`:

```cpp
processingChain.setOutputGain (rawOutputGain->load());
processingChain.setAnalogMode (rawAnalogMode->load() >= 0.5f);
bool analyzerOn = rawAnalyzerOn->load() >= 0.5f;
```

## UI Attachments

The UI components use JUCE's standard attachment classes to bind UI widgets to APVTS parameters:

### HeaderToolbar Attachments

| Widget | Attachment Type | Parameter ID |
|--------|----------------|-------------|
| `analogButton` | `ButtonAttachment` | `analog_mode` |
| `analyzerButton` | `ButtonAttachment` | `analyzer_on` |
| `processModeSelector` | `ComboBoxAttachment` | `process_mode` |
| `outputGainSlider` | `SliderAttachment` | `output_gain` |

### BottomControlStrip Attachments

These are dynamically re-created when the selected band changes via `setSelectedBand()`:

| Widget | Attachment Type | Parameter ID Pattern |
|--------|----------------|---------------------|
| `typeSelector` | `ComboBoxAttachment` | `band_XX_type` |
| `slopeSelector` | `ComboBoxAttachment` | `band_XX_slope` |
| `stereoSelector` | `ComboBoxAttachment` | `band_XX_stereo` |
| `freqSlider` | `SliderAttachment` | `band_XX_freq` |
| `gainSlider` | `SliderAttachment` | `band_XX_gain` |
| `qSlider` | `SliderAttachment` | `band_XX_q` |

When `setSelectedBand(newIndex)` is called:
1. All existing attachments are destroyed (set to `nullptr`)
2. New attachments are created targeting the new band's parameter IDs
3. The combo boxes and sliders automatically update to display the new band's values

### EqCurveDisplay Direct Parameter Access

The curve display modifies parameters directly for drag interactions:

```cpp
// When creating a new band:
auto* activeParam = apvts.getParameter(ParamIDs::bandParam(band, ParamIDs::kActive));
activeParam->setValueNotifyingHost(1.0f);

// When dragging a band handle:
auto* freqParam = apvts.getParameter(ParamIDs::bandParam(band, ParamIDs::kFrequency));
freqParam->setValueNotifyingHost(freqParam->convertTo0to1(newFrequency));
```

The `setValueNotifyingHost()` call atomically updates the parameter value and notifies the host for automation recording.

## Parameter Smoothing

Continuous parameters (frequency, gain, Q) are smoothed in the DSP layer via `juce::SmoothedValue` in `EqBand`:

```cpp
smoothedFreq.reset (sampleRate, 0.02);  // 20ms ramp
smoothedGain.reset (sampleRate, 0.02);
smoothedQ.reset (sampleRate, 0.02);
```

The 20ms ramp time means parameter changes take approximately 882 samples (at 44.1 kHz) to complete. During this period:
- Filter coefficients are updated per-sample (more CPU-intensive)
- After the ramp completes, block processing resumes (more efficient)

Output gain smoothing uses the same 20ms ramp in `ProcessingChain`.

## State Serialization

### Save (getStateInformation)

```cpp
auto state = apvts.copyState();                    // Deep-copy ValueTree
std::unique_ptr<juce::XmlElement> xml (state.createXml());  // Convert to XML
copyXmlToBinary (*xml, destData);                  // Compress to binary
```

### Load (setStateInformation)

```cpp
std::unique_ptr<juce::XmlElement> xml (getXmlFromBinary (data, sizeInBytes));  // Decompress
if (xml != nullptr && xml->hasTagName (apvts.state.getType()))
    apvts.replaceState (juce::ValueTree::fromXml (*xml));  // Replace entire state
```

The `replaceState()` call atomically updates all 298 parameters simultaneously, triggering any active UI attachments to refresh their displayed values.

## BandParameters Struct

The `BandParameters` struct (defined in `source/dsp/EqBand.h`) is the plain-data transfer object between the parameter system and the DSP engine:

```cpp
struct BandParameters
{
    bool active = false;
    FilterType type = FilterType::Bell;
    float frequency = 1000.0f;
    float gain = 0.0f;
    float q = 1.0f;
    int slopeDBPerOct = 12;
    StereoPlacement stereoPlacement = StereoPlacement::Stereo;

    // Dynamic EQ (Phase 8, reserved)
    bool dynamicEnabled = false;
    float dynamicThreshold = -20.0f;
    float dynamicRange = 0.0f;
    float dynamicAttack = 10.0f;
    float dynamicRelease = 100.0f;
};
```

This struct is created on the stack by `BandParameterAttachment::getCurrentParameters()` and passed by const reference to `EqBand::updateParameters()`. It contains no pointers, no allocations, and no virtual methods -- just plain data suitable for audio-thread use.

## Parameter Version Tagging

All parameters are created with version number 1 in their `ParameterID`:

```cpp
juce::ParameterID { ParamIDs::bandParam (i, ParamIDs::kFrequency), 1 }
```

This version number is used by JUCE's parameter versioning system to handle backward compatibility if parameter ranges or meanings change in future releases.
